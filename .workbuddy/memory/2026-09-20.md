### 两个必须记住的项目事实

1. **管理台的构建输出目录是 `backend/app/static/admin/`**，不是 `admin/dist/`
   ——`admin/vite.config.js` 里 `build.outDir` 指过去了（同时 `base: '/admin/'`）。
   所以**解压后必须部署在 `/admin/` 路径下，换路径会白屏**，这点写进了 Release 说明。
2. **APK 是 debug 签名**：`android-build/app/build.gradle.kts` 与 Flutter 工程里 release 的
   `signingConfig` 都指向 `signingConfigs.debug`。发布说明已明确标注，上架前要换正式 keystore。

### 🔴 构建被一个全局 Gradle 配置挡了两周（已修）

Flutter Android 构建报 `Error resolving plugin [flutter-plugin-loader]` +
`repository 'maven' was added by settings file`，**6 秒就失败**，而项目里所有 `*.gradle*`
都查不到 `maven {}`。根因在项目之外：`~/.gradle/init.gradle`（09-17 修改，上一次成功构建是 09-05）
用项目级 `allprojects { repositories { maven {...} } }` 注入国内镜像，撞上 Flutter SDK
`packages/flutter_tools/gradle/settings.gradle.kts` 的 `FAIL_ON_PROJECT_REPOS`（included build）。

已把注入改成 settings 级（`settingsEvaluated` + `dependencyResolutionManagement.repositories`），
国内镜像一个没少，验证通过（45.9s 构建成功）。原文件备份 `~/.gradle/init.gradle.bak-20260920`。
**后半句尤其重要：它能解释「为什么别的项目构建也跟着变慢/报错」——这是全局配置，不是本项目的。**
