# 课堂（Classroom）设计方案 v1.0

> 将原"答疑界面"重置为学习互动核心场所。前端纯渲染、后端智能编排。

## 1. 定位与原则

| 原则 | 含义 |
|---|---|
| 教练主导 | 后端编排引擎决定互动节奏（讲解/出题/检测），学习者跟随 |
| 打断权 | 学习者任何时刻可插入问题，教练切换应答后自动回到主线 |
| 富内容块流 | 互动内容以结构化块呈现（讲解/题目/反馈/小测批），非纯文本 |
| 前端零判断 | 无模式按钮、无意图按钮；前端只渲染块 + 收集输入 |
| 后端智能 | 判断与生成全部由后端 skill 完成，前端不参与决策 |
| 后端记忆 | 记忆/状态/上下文全部存后端（改造点：移除前端本地会话缓存）；前端仅输出渲染与展示层梳理 |

## 2. 界面形态

- Tab 更名：「答疑」→「课堂」（独立全局入口）
- 任务界面"问教练"深链进入课堂，携带课程/知识点上下文
- 顶部课堂头：课程名 · 当前知识点 · 目标进度（可折叠）
- 中部：学习流（块序列，可滚动）
- 底部：消息输入框（唯一输入入口）+ 作答交互随块渲染
- 无模式分隔：三模式消失，专注度判定由后端做

## 3. 块协议（后端 → 前端，SSE 事件 data 内嵌）

```
data: {"type":"block","block":{"kind":"text","content":"...","ref_nodes":["平衡因子"]}}
data: {"type":"block","block":{"kind":"quiz","question":{...},"knowledge":{"id":1,"name":"LL旋转"}}}
data: {"type":"block","block":{"kind":"feedback","correct":true,"score":100,"explain":"...","mastery_delta":+10}}
data: {"type":"block","block":{"kind":"quiz_batch","progress":2,"total":5, ...}}
data: {"type":"block","block":{"kind":"coach_exit","reason":"回到刚才的题"}}
```

### 块类型清单

| kind | 内容 | 渲染 |
|---|---|---|
| text | 讲解/回答正文（可含 [[知识点]] 标注） | 气泡文本 + chip |
| quiz | 单题（choice/fill/short/code/mixed） | 题目卡，自适应作答控件 |
| feedback | 判卷结果 | 对/错 + 解析 + 掌握度变化 |
| quiz_batch | 小测批次（批内题目） | 连测模式：批进度 + 逐题 |
| sediment | 沉淀建议 | 确认卡（复用现有确认流程） |
| coach_exit | 主线衔接句 | 小型幽灵气泡 |

## 4. 后端编排引擎（教练 skill）

### 4.1 判断输入 → 三种处理流

| 用户输入类型 | 后端动作 |
|---|---|
| 普通提问/打断 | 生成讲解块（RAG + 软标注）→ 若之前有主线，追加衔接 |
| 作答（匹配进行中题目） | 判卷 → 反馈块 → 掌握度联动 → 自动决定下一互动（新题/讲解/小测） |
| 新对话（无进行中题目） | 读上下文（任务/知识点/掌握度）→ 教练开场：讲解或直接出题 |

### 4.2 判断规则（skill 内编排逻辑）

- 上下文：最近 8 轮块 + 当前知识点 + 该知识点掌握度 + 会话模式态
- 意图判别（轻量规则 + LLM 兜底）：
  - 消息与进行中题目匹配（填空/选项/文本）→ 判卷流
  - 消息含提问词或自由内容 → 讲解流（保留主线栈）
  - 掌握度 <60 且已完成 2 次讲解 → 出题流
  - 掌握度 ≥60 且连续 3 题答对 → 小测或升难度
- 题型选择（出题时）：掌握度 <50 选择 / 50-70 填空 / >70 简答或代码；混合题由教练按需组合
- 小测：5 题连测，每题独立判卷，批末输出掌握度诊断（可被打断）

### 4.3 主线栈（打断恢复）

- 编排引擎维护"主线"（当前知识点 + 出题/讲解序列）
- 打断时入栈，当前块挂起；答疑完成输出 coach_exit 块恢复主线
- 主线在 30 分钟无互动后自动失效

## 5. 判卷与掌握度联动（复用 M5 技能）

- 客观题：规则判 → 反馈块（含标准答案、解析）→ 掌握度 ± 更新
- 主观题：AI 评分 → 反馈块 → 0.7/0.3 混合更新
- 小测批末：汇总块（对 N/5 + 各题掌握度变化）

## 6. 数据模型变更

- Conversation.mode 字段废弃语义：统一 mode='classroom'（兼容旧 free/quiz/mini_test 数据）
- Message 扩展：type 字段（text/quiz/feedback/batch），content 存块 JSON；历史文本消息 type='legacy'
- 新增 conversation_context：当前主线栈（知识点 id、进行中题目 id、批状态）
- 沉淀建议复用现有流程（生成 → 确认 → 入树 + 复习队列）

## 7. 实施步骤

| 步 | 内容 | 验收 |
|---|---|---|
| C1 | 后端块协议 + 编排引擎骨架（意图判别 + 块生成 JSON Schema） | SSE 输出三类块 |
| C2 | 判卷流接入编排（进行中题目状态机 + 反馈块 + 掌握度） | 作答产生反馈块并自动续题 |
| C3 | 前端课堂页重构（Tab 改名 + 块渲染器 + 主线悬浮气泡） | 页面渲染三类块，无模式按钮 |
| C4 | 小测批 + 主线栈 + 打断恢复 | 批内可打断，主线自动衔接 |
| C5 | 任务卡深链进课堂 + 背景上下文注入 | 从任务进入课堂带知识点 |

## 8. 课堂 × 任务时间轴同步

### 8.1 三轴对齐

```
课程表时间轴 → 学习会话轴（StudySession，调度器驱动） → 课堂记忆轴（每课程容器）
```

- 课程表决定"此刻上什么课"（已有调度器）
- 学习会话是每次上课的骨架（状态机/任务）
- 课堂记忆保证同一门课的跨节连续性（新增）

### 8.2 课堂记忆容器（course_memory）

| 记忆项 | 来源 | 课初注入 |
|---|---|---|
| 上节进度指针 | 最后互动知识点（知识树） | 教练开场衔接 |
| 遗留未完成 | 遗留题目/未确认沉淀 | 恢复进行中块 |
| 薄弱点 | 课程内掌握度最低 N 个节点 | 开场亮出 |
| 到期复习 | review_queue 该课程到期项 | 开场提示先行复习 |
| 主线栈 | 未恢复主线 | 30min 内恢复，否则作废 |

### 8.3 时间同步机制

1. 课堂页加载：查当前 in_class 会话 → 自动激活对应课程上下文（C 系列随带实现）
2. WS 收到 session_status_changed(in_class) → 前台课堂自动切换上下文
3. 课程切换：上下课时间到，课堂头随会话状态切换记忆轴

### 8.4 前端零状态接入

- 课堂页打开：GET /api/v1/classroom/state → 后端返回{conversation_id、课程上下文、历史块、进行中题目、主线栈}
- 前端不持有会话 id（移除 shared_preferences 缓存）；每次进入/重连向后端取状态
- WS 事件驱动重新拉取 state（会话状态变化、主线变化）
- 展示层梳理（渲染/滚动/加载态）为前端职责，业务状态一律后端

### 8.5 界面表达与实施划分

- 课堂头展示当前绑定课程与时段（如"高数 · 09:00-10:20 · 第 2 节"）
- 无活动会话时课堂头为"自由课堂"态：教练无课程上下文，但可主动提议"要不要开始今天的预习"
- **随 C 系列**：Conversation 绑定 study_session_id 写入；课堂打开激活当前课程上下文
- **后置**：course_memory 表 + 记忆序列化/开场注入（AI 生成开场需 key 后验）
