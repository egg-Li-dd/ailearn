二、场景模拟：当前系统的5个典型问题

场景1：阈值断层 — 60-79分的"灰色地带"
  1. 用户做任务检测题，3道题对了2道，得分67分
  2. 任务判定：67 < 80 → 未通过，保持TODO
  3. 错题本判定：67 ≥ 60 → 不收录错题
  4. 复习队列判定：67 ≥ 60 → 不加入复习
❌ 结果：任务卡住了，但用户看不到错题，也没有复习推送，不知道错在哪、怎么改进。任务永远停在TODO。
场景2：掌握度已达标，但任务仍未完成
  1. 用户在课堂答题中多次答对某知识点，掌握度从30涨到85
  2. 但该知识点关联的任务检测题只考过一次，得分65（未通过）
  3. 用户通过其他方式已经掌握了知识点，但任务还是TODO
❌ 结果：任务完成只看检测题分数，不看知识点实际掌握度。用户需要重新做一遍已经掌握的检测题才能完成任务，体验割裂。
场景3：错题重练通过，任务不联动
  1. 任务检测题得分55，未通过，错题进入错题本
  2. 用户在错题本中重练这道题，答对了（得分100）
  3. 知识点掌握度提升了，但任务状态还是TODO
❌ 结果：错题本和任务是两套独立系统。用户已经在错题本证明了掌握，但任务不会自动完成，需要回去重新做检测题。
场景4：多次尝试无进步追踪
  1. 第一次检测：45分（未通过）
  2. 复习后第二次：62分（未通过，但进步了17分）
  3. 再复习后第三次：78分（未通过，但接近通过）
  4. 任务只记录最后一次78分，看不到进步趋势
❌ 结果：attempts=3，但没有分数趋势记录。用户看不到自己的进步，容易挫败。任务完成度是二元的（0或1），没有"已经完成80%"的中间状态。
场景5：逾期任务无补救
  1. 任务截止时间到了，用户没做检测题
  2. 系统标记 is_overdue=True
  3. 没有自动安排复习，没有重新生成检测题
  4. 逾期任务一直挂在列表里，用户不知道怎么补救
❌ 结果：逾期只是一个标记，没有后续动作。逾期任务堆积，学习计划混乱。

三、核心问题总结

  • 1
    任务完成度是二元的，缺少中间进度 P0
    任务要么DONE要么TODO，没有"完成度百分比"。检测题3道对2道（67分），用户已经掌握了2/3，但任务显示0%完成。
  • 2
    任务完成只看检测题，不看知识点掌握度 P0
    知识点掌握度已经85（已掌握），但检测题没考好，任务还是未完成。两个衡量标准脱节。
  • 3
    错题重练不回写任务状态 P1
    用户在错题本重练答对后，任务不会自动完成。已证明掌握，但任务仍卡住。
  • 4
    多次尝试无趋势追踪 P1
    只记录最后一次actual_score，没有历史分数趋势。用户看不到进步，完成度无法体现"接近通过"的状态。
  • 5
    逾期任务无自动补救 P2
    逾期只是标记，没有自动安排复习或重新生成检测题。逾期任务堆积无下文。
  • 6
    完成度统计维度单一 P2
    stats只统计DONE数量，不考虑任务难度、知识点掌握度、答题趋势。无法回答"我整体掌握了多少"。

四、优化方案（按实施优先级）

方案1：引入任务完成度百分比（0-100%）P0
任务不再是二元的DONE/TODO，而是有一个动态完成度。完成度由三个维度加权计算：
• 知识点掌握度（40%）：target_knowledge_id 的 mastery 值
• 检测题最高分（40%）：历次检测中的最高分
• 答题参与度（20%）：是否做过检测题、尝试次数
// 任务完成度计算公式 completion = mastery * 0.4 + best_score * 0.4 + participation * 0.2 // 其中 participation： if attempts == 0: participation = 0 elif attempts == 1: participation = 50 else: participation = min(100, 50 + attempts * 15) // 任务完成判定：completion >= 80 且 best_score >= 60 if completion >= 80 and best_score >= 60: status = DONE
改动量：中 影响：核心体验 涉及：Task模型+task_quiz.py+前端展示
方案2：知识点掌握度达标自动完成任务 P0
当 target_knowledge_id 的 mastery >= 80 时，即使检测题没通过，也自动标记任务为"掌握度达标"状态。
用户可以选择"用掌握度完成任务"，跳过重复检测。
触发时机：
• 每次 apply_mastery_update 后，检查关联任务
• 掌握度从<80涨到≥80时，自动推送"任务可通过掌握度完成"
• 用户确认后，任务标记DONE，actual_score=mastery
改动量：中 影响：学习效率 涉及：mastery.py+task_quiz.py+WS推送
方案3：错题重练通过自动完成关联任务 P1
错题本重练时，如果题目关联的任务检测题全部答对（或平均分≥80），自动将对应任务标记为DONE。
形成"答错→收录→重练→掌握→任务完成"的完整闭环。
改动量：小 影响：闭环体验 涉及：wrong_book.py+task_quiz.py
方案4：记录检测题分数趋势 P1
新增 TaskAttempt 表（或在Task中加score_history JSON字段），记录每次检测的分数和时间。
任务详情页展示分数趋势折线图，让用户看到进步。
完成度计算使用"最近3次平均分"而非单次分数，更稳定。
改动量：中 影响：激励反馈 涉及：Task模型+前端图表
方案5：逾期任务自动补救 P2
任务逾期时自动执行：
• 将关联知识点加入"优先复习"列表
• 重新生成一套检测题（降低难度或减少题量）
• 推送WS通知："任务已逾期，已为你安排复习和重新检测"
改动量：中 影响：计划闭环 涉及：task_auto_progress.py+WS推送
方案6：多维度完成度统计 P2
数据看板新增：
• 按科目的任务完成率（DONE/总数）
• 平均完成度趋势（最近7天）
• 知识点掌握度与任务完成度的相关性
• 逾期任务占比和补救率
改动量：小 影响：数据洞察 涉及：stats.py+管理台看板

五、新旧机制对比

维度 当前机制 优化后
任务完成度 二元（0或1） 百分比（0-100%），三维度加权
完成依据 仅检测题分数≥80 掌握度+检测分+参与度综合判定
掌握度达标 不影响任务状态 掌握度≥80可自动完成任务
错题重练 独立系统，不回写任务 重练通过自动完成关联任务
多次尝试 只记录最后一次分数 记录趋势，用最近3次平均分
逾期处理 仅标记，无后续 自动安排复习+重新检测
60-79分题目 任务未通过+不进错题本 计入完成度+推荐针对性复习
