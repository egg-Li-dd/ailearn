## 一、整体设计方向

### 设计语言统一

与已重构的「AI 设置」页面保持一致：

- **卡片化布局**：圆角 12px，轻阴影，hover 微动效
- **统计卡片**：每个页面顶部 3-4 个彩色统计卡片（图标+数字+副标题）
- **操作栏**：搜索框 + 筛选下拉 + 批量操作 + 主按钮
- **模态框**：统一的添加/编辑模态框，Tab 分组
- **空状态**：友好的空状态插画+引导按钮
- **Toast 通知**：统一的成功/错误提示
- **CSS 变量**：统一主题色、间距、圆角、阴影变量

### 全局增加功能

| 功能 | 说明 |
|------|------|
| **全局搜索** | 侧边栏顶部增加搜索框，可搜索科目/课表/知识点/调用记录 |
| **批量操作** | 所有列表支持多选+批量删除/批量启用/批量导出 |
| **数据导出** | 每个界面支持导出 CSV/Excel |
| **操作日志** | 关键操作（删除/批量修改）记录到审计日志 |
| **快捷键** | `Ctrl+N` 新建、`Ctrl+F` 搜索、`Delete` 删除选中 |

## 二、通用组件开发

> 优先级：P0（最高），所有界面复用，先开发再做界面

### 2.1 StatCard.vue — 统计卡片

**功能**：
- 图标 + 大数字 + 副标题 + 可选趋势箭头
- 4 种配色主题（蓝/绿/橙/紫）

- [Vue-Pure-Admin](https://github.com/pure-admin/vue-pure-admin) — 统计卡片设计
- [Fantastic-admin](https://github.com/fantastic-admin/basic) — 数据卡片组件

### 2.2 SearchBar.vue — 搜索栏

**功能**：
- 搜索输入框（带防抖）
- 筛选下拉按钮（可配置多个筛选项）
- 批量操作按钮（多选时显示）

**借鉴参考**：
- [Vue-Pure-Admin](https://github.com/pure-admin/vue-pure-admin) — 搜索栏+工具栏布局

### 2.3 EmptyState.vue — 空状态

**功能**：
- 大图标 + 标题 + 描述 + 操作按钮
- 多种预设场景（无数据/加载失败/无权限/搜索无结果）

**功能**：
- 预设色板网格（12-20 种教育主题色）

**功能**：
- 统一的模态框容器（标题+内容+底部按钮）

**借鉴参考**：
- [Vue-Pure-Admin](https://github.com/pure-admin/vue-pure-admin) — 模态框组件设计

### 2.6 DetailPanel.vue — 右侧滑出详情面板

**功能**：
- 从右侧滑入的详情面板
- 遮罩层 + 滑入动画
- 标题栏 + 内容区 + 底部操作区
- 支持嵌套子面板
- 宽度可配置（400px/500px/600px）

**借鉴参考**：

### 4.5 技术要点

#### 拖拽实现

使用原生 HTML5 Drag & Drop API，不引入第三方库：

```javascript
// 拖拽开始
function onDragStart(e, itemId) {
  e.dataTransfer.setData('text/plain', itemId)
  e.dataTransfer.effectAllowed = 'move'
}
// 拖拽放置
function onDrop(e, weekday, startTime) {
  e.preventDefault()
  const itemId = e.dataTransfer.getData('text/plain')
  // 调用 API 更新课表项
}
```

#### 网格布局

使用 CSS Grid 实现：

```css
.schedule-grid {
  display: grid;
  grid-template-columns: 80px repeat(7, 1fr);
  grid-auto-rows: 60px;
  gap: 2px;
}
```

#### 导出图片

使用 [html2canvas](https://github.com/niklasvh/html2canvas) 库：

```bash
npm install html2canvas
```

## 六、知识树界面重构

> 文件：`views/KnowledgeView.vue`

> 预估工作量：3 天

- 树形列表只有 **3 层硬编码**（lvl1/lvl2/lvl3），不支持任意深度

### 6.6 思维导图实现方案

**方案 A：集成 markmap（推荐，轻量）**

```bash
npm install markmap-lib markmap-view
```

```javascript
import { Transformer } from 'markmap-lib'
import { Markmap } from 'markmap-view'

const transformer = new Transformer()
const { root } = transformer.transform(markdownContent)
const svg = document.querySelector('#mindmap-svg')
Markmap.create(svg, null, root)
```

**方案 B：自研 SVG 思维导图**

- 使用 SVG + 力导向布局
- 支持节点拖拽、缩放、平移
- 节点点击展开/折叠
- 开发成本较高，但可完全定制

**推荐方案 A**，markmap 成熟稳定，与 Markdown 数据格式天然兼容。

## 七、全局功能

### 7.1 全局搜索

**位置**：侧边栏顶部

**功能**：
- 搜索科目（名称/代码）
- 搜索课表项（科目/地点/教师）
- 搜索知识点（名称）
- 搜索 AI 调用记录（模型/功能类型）
- 搜索结果分组展示，点击跳转对应界面

**实现**：
- 前端本地搜索（数据量小时）或后端搜索 API（数据量大时）
- 防抖 300ms
- 快捷键 `Ctrl+K` 或 `Ctrl+F` 聚焦搜索框

### 7.2 批量操作

**功能**：
- 所有列表支持多选（复选框）
- 批量删除（带确认弹窗）
- 批量启用/停用
- 批量导出
- 批量移动（知识树）

**实现**：
- 封装 `useBatchSelect` composable
- 选中时顶部显示批量操作栏

### 7.3 数据导出

**功能**：
- 每个界面支持导出 CSV
- 课表支持导出 Excel/图片/PDF
- 知识树支持导出 Markdown/OPML/JSON

**实现**：
- CSV：前端原生生成（Blob + URL.createObjectURL）
- Excel：使用 [xlsx](https://github.com/SheetJS/sheetjs) 库
- 图片：使用 [html2canvas](https://github.com/niklasvh/html2canvas)
- PDF：使用 [jspdf](https://github.com/parallax/jsPDF) + html2canvas

### 7.4 快捷键

| 快捷键 | 功能 |
|--------|------|
| `Ctrl+N` | 新建（当前界面的新建操作） |

| `Delete` / `Backspace` | 删除选中项（带确认） |
| `Escape` | 关闭模态框/侧滑面板 |
| `Ctrl+S` | 保存（编辑状态下） |
| `Ctrl+E` | 导出当前数据 |

**实现**：
- 封装 `useKeyboardShortcuts` composable
- 全局事件监听，按当前激活界面分发

### 7.5 审计日志（可选）

**功能**：
- 记录关键操作（删除/批量修改/AI 生成）
- 记录操作人、时间、操作类型、操作对象、变更前后数据
- 管理台设置页面可查看审计日志

**实现**：
- 后端 `audit_logs` 表
- 前端设置页面增加审计日志 Tab

```
                      └──> P2 全局功能
                             │
                             └──> P3 打磨优化
```

### 每个界面的实施步骤

1. **数据模型确认**：确认后端 API 返回的数据结构
2. **通用组件开发**：如果该界面需要新的通用组件，先开发
3. **主视图重构**：替换模板，使用新的布局和组件
4. **子组件开发**：开发该界面特有的子组件（卡片/表单项/模态框等）
5. **交互实现**：搜索/筛选/批量/拖拽等交互
6. **样式打磨**：hover 效果/动画/响应式
7. **浏览器验证**：在管理台中验证功能完整性

## 附录：关键决策记录

### 决策 1：不引入 UI 组件库

**原因**：
- 现有代码使用原生 CSS，引入 UI 库（Element Plus / Ant Design Vue）会导致样式冲突
- 管理台界面相对简单，自研组件成本可控
- 保持轻量，构建产物体积小

**替代方案**：
- 提取通用组件（StatCard/SearchBar/FormModal 等）
- 建立 CSS 变量体系和通用样式
- 参考成熟 UI 库的设计规范，但不引入依赖

### 决策 2：思维导图使用 markmap 而非自研

**原因**：
- markmap 成熟稳定，13.1k Star，社区活跃
- 与 Markdown 数据格式天然兼容，知识树数据可直接转换
- 轻量级，渲染引擎仅几十 KB
- 支持缩放、拖拽、节点点击等交互

**自研成本**：
- SVG 力导向布局算法开发量大
- 节点碰撞检测、连线计算复杂
- 维护成本高

### 决策 3：拖拽使用原生 HTML5 Drag & Drop 而非 vuedraggable

**原因**：
- 课表网格拖拽需要自定义放置逻辑（时段/星期计算），原生 API 更灵活
- 知识树拖拽需要校验循环引用，原生 API 更可控
- 减少第三方依赖
- vuedraggable 适合列表排序，不适合网格和树形结构的复杂拖拽

**例外**：
- 科目卡片的简单排序可以考虑 vuedraggable
- 但为了技术栈统一，全部使用原生 API
