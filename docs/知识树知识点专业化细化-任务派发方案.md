## 一、任务背景

本项目是一个考研 AI 学习系统（后端 FastAPI + SQLite + Flutter App），核心功能之一是**知识树**：按科目→章节→小节→知识点的层级结构组织学习内容，并为每个知识点维护掌握度、复习队列（FSRS）和 AI 出题。

**当前痛点**：系统已有 826 个知识节点，但**所有节点的 `summary` 和 `notes` 字段均为空（细化率 0%）**。AI 出题时只能基于知识点名称自由生成，导致：
- 出题范围不可控，容易超纲
- 题目质量不稳定，专业深度不足
- 无法利用已有的"模板驱动出题"机制（零 token、确定性输出）

系统已内置知识点细化机制（`knowledge_refine.py`），通过 Function Calling 生成结构化参数表，但尚未批量执行。本任务的目标是**人工/AI 协同完成所有知识点的专业化内容填充**，使知识树从"骨架"升级为"有血有肉的专业知识库"。

## 三、任务目标

- 填充 `prerequisites` 字段（前置知识点 ID 关联）

## 四、内容质量标准（专业化要求）

### 4.1 总体原则

- **考研级别**：所有内容必须达到考研专业课/公共课的专业深度，参考教材包括：
  - 数据结构：严蔚敏《数据结构（C语言版）》、王道/天勤考研
  - 高数二：同济大学《高等数学》、张宇/汤家凤考研
  - 计算机网络：谢希仁《计算机网络》（第8版）
  - 操作系统：汤小丹《操作系统》、王道考研
  - 计算机组成原理：唐朔飞《计算机组成原理》、白中英
  - 英语：考研英语大纲（阅读/写作/翻译/完形）
  - 政治：考研政治大纲解析（马原/毛中特/史纲/思修/时政）
- **准确性优先**：宁可简洁，不可出错。定义、公式、术语必须准确无误。
- **自包含**：每个知识点的定义不依赖"参见XX"或"与XX类似"等表述。
- **范围边界明确**：必须明确说明本知识点**不涉及**什么，防止出题超纲。

### 4.2 各字段质量要求

#### `definition`（核心定义）
- 25-100 字，准确、精炼、自包含
- 必须是本知识点**自身**的定义，不能引用其他知识点作为定义主体
- 示例（好）："栈是限定仅在表尾进行插入和删除操作的线性表，允许插入和删除的一端称为栈顶（top），另一端称为栈底（bottom），不含元素的栈称为空栈。"
- 示例（差）："栈是一种特殊的线性表，和队列类似但操作受限。"（引用了其他知识点，不合格）

#### `core_elements`（核心要素）
- 2-5 个，每个是本知识点的关键组成部分或本质特征
- 用短语表述，不是完整句子
- 示例（栈）：`["后进先出(LIFO)", "栈顶操作", "空栈判定", "上溢/下溢"]`

#### `key_terms`（关键术语）
- 1-5 个，本知识点涉及的核心专业术语、概念名或符号
- 示例（栈）：`["栈顶 top", "栈底 bottom", "进栈 push", "出栈 pop", "空栈"]`

#### `formulas`（相关公式）
- 数学/物理/化学/经济学等有公式的学科填写，纯概念类留空数组 `[]`
- 使用 LaTeX 格式或纯文本公式
- 示例（时间复杂度）：`["T(n) = O(f(n))", "最坏时间复杂度", "平均时间复杂度"]`
- 示例（导数）：`["f'(x) = lim(Δx→0) [f(x+Δx)-f(x)]/Δx", "(uv)' = u'v + uv'"]`

#### `common_mistakes`（常见错误/误区）
- 1-3 个，学习者容易混淆、记错或理解偏差的点
- 必须具体，不能泛泛而谈
- 示例（栈）：`["混淆栈和队列的进出顺序", "误以为栈可以在中间插入元素", "空栈执行出栈操作导致下溢"]`

#### `scope_boundary`（范围边界）
- 明确说明本知识点**不涉及**哪些内容、不深入哪些前置知识的细节、不与哪些相似概念做对比
- 这是**防止出题超纲的关键**，必须认真填写
- 示例（栈的定义）："本知识点仅涉及栈的基本定义和术语，不涉及栈的存储结构实现（顺序栈/链栈）、不涉及栈的应用场景（表达式求值/递归/括号匹配）、不与队列做对比。"

#### `prerequisites_desc`（前置知识简述）
- 一句话概括学习本知识点需要预先掌握的知识，不展开细节
- 示例（栈）："需要掌握线性表的基本定义和操作。"

## 五、输出格式规范

### 5.1 `notes` 字段 JSON 格式

必须严格遵循以下结构（与系统 `knowledge_refine.py` 的 `PARAMS_SCHEMA_VERSION = "1.0"` 兼容）：

```json
{
  "schema_version": "1.0",
  "refined_at": "2026-08-27T12:00:00+08:00",
  "params": {
    "definition": "核心定义，25-100字……",
    "core_elements": ["要素1", "要素2", "要素3"],
    "key_terms": ["术语1", "术语2"],
    "formulas": ["公式1", "公式2"],
    "common_mistakes": ["误区1", "误区2"],
    "scope_boundary": "本知识点不涉及……",
    "prerequisites_desc": "前置知识简述……"
  }
}
```

**字段约束**：
- `schema_version`：固定为 `"1.0"`
- `refined_at`：ISO 8601 格式时间戳
- `definition`：必填，字符串，≥15字（建议 25-100 字）
- `core_elements`：必填，字符串数组，≥2 个
- `key_terms`：必填，字符串数组，≥1 个
- `formulas`：可选，字符串数组，无公式时为 `[]`
- `common_mistakes`：可选，字符串数组，无时为 `[]`
- `scope_boundary`：必填，非空字符串
- `prerequisites_desc`：可选，字符串，无时为 `""`

### 5.2 `summary` 字段

直接填入 `params.definition` 的值（纯文本，不是 JSON）。

### 5.3 批量交付格式

建议按科目分批交付，每批输出一个 CSV 文件或 JSON 文件，格式如下：

**CSV 格式（推荐，可通过管理台"导入参数"功能直接导入）**：

```csv
id,name,summary,notes,icon,difficulty
1,第1章 绪论,本章概述……,{"schema_version":"1.0",……},📚,1
2,1.1 什么是数据结构,数据结构是……,{"schema_version":"1.0",……},🏗️,2
```

**注意**：
- `id` 必须与数据库中现有节点 ID 对应
- `notes` 列的 JSON 中的双引号需要在 CSV 中正确转义（用 `""` 表示一个 `"`）
- 如果不确定节点 ID，先查询数据库确认

**JSON 格式**：

```json
[
  {
    "id": 2,
    "name": "1.1 什么是数据结构",
    "summary": "数据结构是……",
    "notes": "{\"schema_version\":\"1.0\",……}",
    "icon": "🏗️",
    "difficulty": 2
  }
]
```

## 八、注意事项与协作约定

### 8.1 数据安全

- **写入前必须备份数据库**，备份文件命名格式：`ailearn.db.bak-YYYYMMDD-HHMMSS`
- 不要直接在生产数据库上测试，建议先在备份上验证
- 如果使用 SQL 直接更新，务必使用事务（`BEGIN`/`COMMIT`），出错可回滚

### 8.2 多 Agent 协作

- 本项目可能有多个 Agent 同时操作工作区
- 写入数据库前，检查 `.agent-status.json` 确认无冲突
- 如果其他 Agent 正在操作数据库，等待其完成后再写入
- 完成后更新 `.agent-status.json` 释放占用

### 8.3 内容一致性

- 同一概念在不同知识点中出现时，定义必须一致
- 术语翻译统一（如"栈"对应 stack，"队列"对应 queue）
- 公式符号统一（如时间复杂度用 `O(f(n))`，不用 `O(n)` 简写除非上下文明确）

### 8.4 层级处理策略

- **L2（章）**：可选填写 `summary`（本章概述，50-150字），`notes` 可留空或填章节级参数表
- **L3（节）**：必须细化，填写完整参数表
- **L4（知识点）**：必须细化，填写完整参数表，这是核心
- 如果某 L3 节点下没有 L4 子节点，则该 L3 节点本身就是知识点，必须细化

### 8.5 英语/政治科目处理

- 这两个科目当前没有任何节点
- 如果需要处理，**先建立知识树结构**（章节→小节→知识点），再进行细化
- 英语建议结构：词汇→语法→阅读→写作→翻译→完形填空
- 政治建议结构：马原→毛中特→史纲→思修→时政
- 建树时通过管理台"AI 建树"功能或手动添加节点，然后再批量细化

## 九、快速开始模板

### 查询待细化节点（Python）

```python
import sqlite3

conn = sqlite3.connect('backend/data/ailearn.db')
conn.row_factory = sqlite3.Row
cur = conn.cursor()

# 查询某科目所有待细化节点
subject_id = 1  # 数据结构
rows = cur.execute('''
    SELECT id, subject_id, parent_id, name, level, difficulty
    FROM knowledge_nodes
    WHERE subject_id = ? AND level >= 3
      AND (notes IS NULL OR notes = '')
    ORDER BY sort, id
''', (subject_id,)).fetchall()

for r in rows:
    print(f'[{r["id"]}] L{r["level"]} {r["name"]}')

conn.close()
```

## 十、交付物清单

每完成一个批次，交付以下内容：
