优化要点

  • 知识点讲解要求从 200 字（①②③④逐条展开）压缩为 40 字规则句（定义→要点→例子→误区）
  • 总结知识点要求从 250 字（5步流程完整描述）压缩为 50 字（自动基于任务列表，不需用户指定）
  • 动态上下文（课程名/知识点）从末尾拼接改为【上下文】分区，与静态规则明确分隔
  • 保留所有核心约束（详细展开、禁止一句话概括、自动确定范围），不影响输出质量

实际 AI 输出对比（真实调用数据）
使用优化前后的 prompt 实际调用 AI 模型，对比输出内容和 token 消耗

关键发现：输出 Token 控制与输入 Token 优化同等重要

  • 优化后的 prompt 确实降低了 prompt_tokens（输入）：单选 214→186，填空 340→242
  • 但 completion_tokens（输出） 可能因模型行为差异而波动，甚至反增（填空 265→1306，含模型 reasoning token）
  • 因此 prompt 优化必须同时控制输出格式（紧凑JSON）和输出长度（explanation≤80字）
  • System prompt 支持模型端缓存（优化前填空调用已命中 cached_tokens=256），连续同场景调用时实际输入成本更低
  • 结论：结构优化方向正确，但需要在真实业务中多次采样取平均值，并严格约束输出长度

额外收益（非 Token 层面）

  • System prompt 支持模型端缓存（如 OpenAI Prompt Caching / DeepSeek Cache），连续同场景调用时 system 部分近乎免费，实际节省可能高于 55%
  • 结构化分区降低 AI 指令混淆概率，输出格式准确率提升（减少 JSON 解析失败重试的二次消耗）
  • 静态规则与动态参数分离，后续修改参数不触碰规则，维护成本降低
